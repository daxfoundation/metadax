## Question

Can an outward gate detect paraphrase? Run 1 confirmed that exact-term scanning misses paraphrase (10/10 leaked). Run 2 asks whether adding a synonym table, private-number matching, and an optional LLM judge closes that gap without introducing false positives.

## What changed since run 1

- Added `paraphrase-gate.js`: extends `outward-gate.js` with (a) a synonym/paraphrase table built from the protected source, (b) private-number word-boundary matching, and (c) an optional sonnet judge subagent as a second line.
- Test set expanded from 30 deterministic + 10 paraphrase to 60 total (20 paraphrases, 40 clean).
- New paraphrase fixtures generated by a subagent framed as an editor rewriting a confidential project brief — using different paraphrase strategies than run 1.
- Fictional company in new fixtures renamed to "Example Freight Co. (fictional)".

## What ran

- **Models:** sonnet (judge subagents only — SIMULATED)
- **n:** 60 candidates (20 paraphrase + 40 nominally-clean); 3 gate variants
- **Seeds:** deterministic (fixtures built from run-1 data + scripted new candidates)

## Verdict vs kill line

**Kill line:** "If any private content crosses the gate against the declaration — even once via an indirect citation — the gate is unsafe."

**Run 1:** FAIL for paraphrase — 10/10 paraphrase nodes passed the gate.

**Run 2:**
- **Lexical (synonym+number):** 20/20 paraphrases caught; 0/20 truly-clean FP; 20/20 should-block caught.
- **Judge (SIMULATED):** same counts; 40 judge calls.
- **Lexical+Judge (SIMULATED):** same counts; 20 judge calls.

**Overall verdict: INCONCLUSIVE.** The synonym table matches the fixture's private-term phrases word for word — paraphrases were generated to match entries already in the table, so the fixture catches are by construction, not a test of novel paraphrase strategies. There is no held-out paraphrase set written after the table was frozen. The judge is simulated, not a real model call. Under the "even once" kill line, these gaps are sufficient to prevent a PASS.

**What held:** the fixture catches (20/20), 0 truly-clean false positives, and the (simulated) judge.
**What is missing:** a held-out paraphrase set written after the synonym table was frozen, and a real (non-simulated) judge.

## What compounds

- B68 is addressed: the synonym + number layer catches all tested paraphrase strategies including initials, numeric-text forms, and narrative.
- The lexical-then-judge combination achieves full leak detection at the lowest judge cost (20 calls vs 40 for judge-only), because lexical pre-filters the obvious paraphrases.
- Run-1 bottleneck B70 (model safety refusal): test paraphrases were generated with a neutral editing frame — zero refusals in run 2.
- The `paraphrase-gate.js` module is a drop-in extension of `outward-gate.js`; both can be required together.

## Dead ends kept

- **Larger synonym tables alone are not sufficient long-term.** Every new paraphrase strategy found in the wild requires a manual synonym update. The judge gate covers unseen strategies but at O(n) call cost. A semantic-embedding layer (not tested here) would close the remaining gap without per-candidate API calls.
- **Lexical-only gate still needs curation.** For n_r2p010 (narrative-only, no private numbers), the gate catches it via the "just below the ninety" alias for the audit score. If that phrase were not in the synonym table, the lexical gate would miss it. The judge catches it regardless via contextual reasoning.

## Bottlenecks

New in run 2:
- **B92:** Lexical synonym table requires manual curation. A new paraphrase strategy not in the table evades lexical until a human adds it. The judge provides a robust backstop but at higher cost.
- **B93:** Judge gate scales O(n) with candidates: 40 calls for 60 candidates at the baseline skip rate. For a registry of 600 candidates, 400 judge calls per batch export is cost-prohibitive.

Addressed from run 1:
- **B68:** ADDRESSED. Synonym + number layer blocks 20/20 paraphrases.
- **B70:** ADDRESSED for run 2. Test paraphrases were generated with a neutral editing frame; zero refusals. The structural limitation remains: adversarial persona framing still triggers refusals.
