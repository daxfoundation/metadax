# E04 first run -- 2026-09-27

## Outcome: NOT RUN

No model executed the suite. The eval harness, the 27 cases, the grader, the
local runner, the promptfoo config and the dispatch-only certification workflow
were all built and are committed, but the first end-to-end execution against a
model did not happen, because the nested `claude -p` in the build environment
was not logged in.

Per docs/ACCURACY.md item 3, no result is presented that a recorded run did not
produce. There are no schema-valid rates, no rubric scores and no per-model
failures to report yet. E04's Status stays "not started".

## Why it did not run

The plan was to execute the suite with the same `claude` binary the build
environment runs (`claude -p`). The nested invocation is not authenticated:

```
$ claude --version
2.1.170 (Claude Code)

$ claude -p "reply with the single word ok" --output-format text
Not logged in · Please run /login
(exit code 1)
```

The runner sees the same failure per case (it records a `run:` error rather than
inventing a reply):

```
$ node evals/run_claude_p.js --op MP-01 --model default
{"case":"MP-01/adult-create-from-description","pass":false,"schema_valid":false,"reasons":["run: exit 1: "]}
{"case":"MP-01/minor-create-from-description","pass":false,"schema_valid":false,"reasons":["run: exit 1: "]}
{"case":"MP-01/update-consent","pass":false,"schema_valid":false,"reasons":["run: exit 1: "]}
WARNING: no case reached a model; summary reflects run errors only.
```

Because no model reply was produced, that error-only run directory was not
committed: committing it would present a "run" that never reached a model.

## Prompt defect vs case defect

Cannot be distinguished without a model run. Two case/tool limitations were found
while building (they are tool gaps, not prompt defects), documented in
`evals/README.md` and each case's `input.json`:

- MP-02 `suggest`: `tools/assemble.js` does not emit a CONTENT block for MP-02,
  so the suggest case is assembled from COURSE + INPUT only.
- MP-04 `generate`: `tools/assemble.js` always injects the objective's existing
  node as CONTENT, so a generate case looks closer to a re-render.

This section was added after the run above; the run itself is unchanged.

- `tools/assemble.js` no longer injects an existing node as CONTENT for MP-04
  `generate`, which closes the second gap listed above.
- `tools/assemble.js` now accepts a CONTENT block for MP-02 `suggest` and
  `revise` (via `--content`). The `suggest` case does not pass one yet, so the
  first gap is only half closed.

  change above, a clarification in MP-02 and MP-04 (`bloom_target` capitalisation)
  and the kernel's switch to ASCII (`<=` for the old symbol). The runners read
  `stack.txt` as-is, so run `node evals/build_cases.js` before any model run; the
  certify workflow now does this itself.
