## Verdict vs stop rule

**FAIL** — no operation reaches 90% schema-valid on either pass.

However: the dominant failure cause is **not a model conformance miss** but a simulation methodology artifact (see B28 below). The runner subagents received instructions to "read the file and then act as the engine", which caused them to emit reasoning preamble before the JSON. grade.js parse gate requires output to start with `{`. In run 2, subagents received the stack content directly and MP-05 ran 12/12 = 100% schema-valid; in this run, 10 of 12 MP-05 cases fail at the parse gate due to preamble.

The two specific fixes tested are confirmed:
- **B05 confirmed fixed**: MP-02/design-size-short passed sv=true in both passes; raw_head shows `"id":"photosynthesis-energy-intro"` and lesson ids `L01`, `L01.M01`, etc. — no `course:` or `concept:` prefixes.
- **B06 confirmed fixed**: MP-04/render-for-learner passed sv=true in both passes, validated against the new `rendering-output.schema.json`.

## What compounds

- B05 fix gates all MP-02 conformance; confirmed clean for design mode.
- B06 fix gates schema measurement for suggest and render; render is now correctly measured.
- The runner preamble finding (B28 below) identifies the methodology change needed for run 4: pass stack content directly to subagent as the full prompt, no file-read wrapper.

## Dead ends kept

- MP-07 cases fail at parse because the CONTENT block in the assembled stack contains lesson sections (from the node), not a graded practice item. The assemble.js logic for MP-07 builds CONTENT the same way as MP-04/06 (from the node's core sections), but MP-07 expects `{id, concept, bloom_level, question_type, grading, question, answer}`. This may be an assemble.js fixture gap.
- MP-06/hint continues to be ambiguous: the fixture SESSION ends in a `done` state; the model reasons about this at length before (sometimes) emitting JSON.
