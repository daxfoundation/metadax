# E05 run record -- 2026-10-09

Automated: a model answered each case and a deterministic grader scored the replies. No person took part. This is not a pilot, and it does not measure precision or recall.

Written 2026-10-20 from the run notes (the maintainer's working notes, not published) and the saved model replies, which are committed beside this file in `2026-10-09-raw/`. The run was not recorded in this repository when it happened; this file closes that gap. `2026-09-27-first-run.md` stays as written: it records an earlier attempt that did not reach a model.

E05 shares its run with E04: the follow-up engine (MP-05) is one of the six operations in the E04 suite, and its 12 cases are the E05 cases. The method, the grader, the harness commits and the fix between run 1 and run 2 are described in full in [the E04 run record](../../E04/results/2026-10-09-run.md); this file does not repeat them.

## Outcome

- **Run 1:** all 12 MP-05 cases ran. 9 pass, 3 fail.
- **Run 2:** the 3 failures were run again after the grader fix and the prompt edit described in the E04 record. 3 pass.
- E05's own measure is precision and recall of the reuse, extend and new decisions against a 50-node planted registry (20 near-duplicates, 10 different-intent traps), with the stop rule "kill if precision is under 0.8 or recall is under 0.7". **That sweep was not run** (`evals/e05/plants.json` was not executed), so the stop rule cannot be applied to this run.
- One vendor's model only (named in the E04 record).

## What ran

The 12 cases in `evals/cases/MP-05/` at commit `fee91e8`, built from the fixture course `fixtures/courses/cell-biology-obsidian`. One reply per case in run 1; in run 2, one reply for each of depth5-end-of-chain, empty-input and over-500-char-input. Each reply was graded by `evals/grade.js` against that case's `expect.json` (parse, schema, id gates, then the case rule). Run 1 used the grader as committed (`grade.js` blob `b6f20ab`); run 2 used it with the envelope and error-object change (blob `240372b`).

## Reading the verdicts

- **Nine passes in run 1.** Six of the nine carry a rule on `decision`: cross-module-extend, depth2-new-question, out-of-scope-redirect, parent-answers-ancestor, sibling-reuse and title-slug-collision. Each rule is a set of allowed values, not one right answer (cross-module-extend allows extend, reuse and new). The other three (other-language-input, private-branch-question, prompt-injection) were checked on shape and on their other rules (type, id prefix, visibility, text that must not appear), not on the decision.
- **depth5-end-of-chain and over-500-char-input failed at the parse layer.** The saved replies are not "answer plus trailing prose": the braces are unbalanced and the rest of the answer follows the first object (see item 1 of "Notes on the record" in the E04 record). The first object's `decision` was `new` in both, but the grader stopped before it reached the case rule. In run 2 both replies parse and pass: depth5 returned `new` at depth 5, over-500 returned `new` with a 500-character resolved question.
- **empty-input failed at the schema layer, in the grader.** The model returned an `error` object, which the case allows (`type` followup or error). Run 1's grader validated it against the follow-up schema anyway and reported the follow-up keys missing. The run 2 grader checks an error object against `error.schema.json`, and the case passes.

## Regrade: the grader fix on its own

On 2026-10-20 the 12 run 1 replies were graded again with the run 2 grader. This is a regrade of saved replies, not a new run. empty-input now passes (10 of 12); depth5-end-of-chain and over-500-char-input still fail at the parse layer, unchanged. The other nine are unchanged. So the grader fix explains empty-input, and the two parse failures needed a different sample, which is what run 2 provided.

## What this does not show

- **No precision, no recall, no stop-rule verdict.** The planted-registry sweep did not run. The runs of 2026-10-18 and 2026-10-19 (`2026-10-18-reuse-decisions.md`, `2026-10-19-reuse-decisions-run2.md`) report those measures on a 60-query set; this file does not.
- **A decision in the allowed set is not a proof the decision is right.** The grader does not check that a `reuse` target actually answers the question, beyond the id and visibility rules.
- **Small and narrow.** 12 hand-built cases from one course (cell biology), one sample each, one vendor's model.
- **Run 2 is three re-runs.** Each of the three cases ran once after the change. That shows they can pass, not how often.
