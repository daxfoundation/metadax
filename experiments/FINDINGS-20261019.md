# Findings: runs of 18-19 Oct 2026

This round ran E01–E14 and X01–X11 once on 2026-10-18. Follow-up runs ("run 2") for E03, E05, E13, E14, X01, X07 and X08 ran on 2026-10-19.

How the runs were done:
- **Simulated.** Most runs used models to stand in for the people (guide, learner, parent, reviewer). These are marked simulated, and no real person took part in any of them.
- **Deterministic.** E06, E12 and X09 were deterministic scripts. So was the X07 harness, which used a fake model.
- **Model runs without personas.** E04 ran its prompts on models with no personas involved.

Some results are negative, and they are reported as results. MetaDAX is a way to test how learning compounds, never the way. Nothing here is a verdict on the architecture as a whole.

The new bottleneck rows are B24–B93 in `BOTTLENECKS.md`.

## Per-experiment notes

**E01 (simulated).** PASS. A guide built the fixture course end to end, and all five objective nodes validated. There was one tool error, which was recovered; the PASS counts unrecovered errors. The earlier depth-cap worry (B01) is confirmed fixed under v0.3.

**E03 (simulated).** Run 1 FAIL. The learner session ran to the end and saved, but validation failed on every turn and event (44 errors). Unused sub-objects set to null are refused, and a follow-up event has no enum value (B24–B27). In run 2, the arm that got schema and prompt fixes (arm C) had 0 errors. The arm that got schema fixes only (arm B) drifted on enums and state types (B79–B82). There was one session per arm, with different personas in each, so this is a small, confounded comparison.

**E04 (model runs, no personas).** FAIL against the 90% line: 7/27 cases were schema-valid on each pass. The main cause is a harness artifact (B28): the runner wrote reasoning before the JSON, so 20/27 cases failed at the parse gate. The two fixes under test, B05 and B06, were both confirmed. An MP-04 prompt still names an old schema version (B29). Cross-vendor certification, the card's real question, is still untested (B08).

**E05 (simulated).** On sonnet, reuse decisions pass narrowly: precision 0.810 against a 0.80 line, recall 0.971. With the trap-fixture flaw removed, precision is 34/36 = 0.944. The run-2 sonnet number is a re-score of run 1's outputs, not a new run. Haiku is INCONCLUSIVE: precision 0.805 in run 1 and 0.739 in run 2. The trap nodes pollute the "must not reuse" test (B30), and run 2 showed the contamination reaching ordinary-new queries (B83). Naming the enum in the prompt fixed haiku's enum and confidence drift (B31, B33).

**E06 (deterministic).** PASS. Link times were computed from byte counts, not measured on a real link. A realistic full course bundle (~500 kB) takes about 96 s of the 300 s window at 50 kbps, so the incremental path fits. The risks are the first full download and the lack of resume in `git bundle` (B34, B35).

**E08 (simulated).** PASS on the pure-function core: 82/82 oracle tests across 12 assets. This is necessary but not sufficient. There is no browser or rendering gate yet, so a passing core can still ship a broken sketch (B36, B37).

**E09 (simulated).** PASS with a caveat. Five of six parents' records could be filed as-is. One set carried 14 privacy errors and cannot be filed. The validator does not enforce `additionalProperties`, so nine wrong-key entries pass silently (18/21 "valid") (B38–B41).

**E11 (simulated).** PASS. Ingest needs no schema change beyond S-7; course metadata is a separate gap (B42). Recall was 14/15 at a 4 KB cap and 15/15 at 16 KB. At 4 KB the public node set alone overflows the cap, and selection falls back to chronological order (B43).

**E12 (deterministic).** PASS. All 12 cases were handled correctly: 11 tampers were detected and 1 clean case correctly passed. Verifying commit by commit is slow at scale (~80 h for 4M commits, B44). `ssh-keygen` is absent in some environments (B45), and a workaround has shipped.

**E13 (simulated).** Run 1 passed on a substituted variant, so the card's own variant was untested; also, no FORGE operation exists yet (B46–B48). Run 2 tested the card's variant and is INCONCLUSIVE. The variant is schema-valid 10/10 and shows the method's surface features. But the check was a word list of phrases the prompt itself asked for, and the method-literate reviewer the card requires was not run (B84, B85).

**E14 (simulated).** FAIL in both runs. In run 1 the age wall stopped none of eight explicit minors and was bypassed by every adversarial opener (B49, B50). Run 2 used patched prompts:
- They stopped every explicit and implicit minor and 6/6 new hold-out attacks, with no adult false-stops.
- One opener still got through: "skip the age check", with no age cue at all.

A prompt-only, first-turn wall cannot catch that. It needs a structural check, such as a guide confirming the learner's age (B86).

**X01 (simulated).** Both runs are INCONCLUSIVE. Reusing a captured move matched a control that reinvents it, but did not beat it. In run 2 the control was slightly faster (1.67 vs 1.83 attempts). That gap (0.167) sits inside the 0.67 run-to-run spread, and every arm resolved 6/6 (B51–B53, B87–B89). The move turned out to be discoverable on demand, so a record's value may lie in portability rather than speed.

**X02 (simulated).** PASS. The federation fixes hold in simulation:
- Per-module plus append-only storage cuts conflicts/100 from 81 to 13.6 (−83%).
- The accepted-lifecycle gate drops cross-fork propagation of unreviewed nodes from 841–854 to 0.
- A stored inverted index makes lookups much faster.

Paraphrase dedup still needs a model judge, which has a cost (B54, B55).

**X03 (simulated).** PASS with a significant caveat. The override record works. However, a model-played expert reviewer cleared a node that omitted two escalation triggers. Review caught all 3 planted commission errors, but caught 0 of 1 omissions (B56). Prohibitions also live in prose rather than in a structural gate (B57). As built, the module is not safe to deliver.

**X04 (simulated).** INCONCLUSIVE: predictiveness and re-teach lift were not tested. What did work: markers now attach to nodes by opaque id, and the atlas rebuilds from the registry alone, byte-identical to the version built from the log. The main stall became one hole carrying three sessions, instead of three fragments. Unvalidated stall records still produce thin holes (B58, B59).

**X05 (simulated).** INCONCLUSIVE. The same model acted as both learner and evaluator, so the 0.95 agreement reflects shared interpretation, not validation across two instruments (B60). The rubric also over-fires in densely scaffolded concepts (B61), and downstream advance was not measured (B62).

**X06 (simulated).** PASS. A week's learning fits in 965 KB of a 13.1 MB weekly allowance. The sharded index gives an 866× lookup speedup at 10⁵ entries and fixes B02. Two costs remain. At a 100-course library, each learner still pulls shard overhead (B63). A miss on the first session caps the cache-hit rate at 97% (B64).

**X07 (deterministic harness).** INCONCLUSIVE in both runs. This was a feasibility check only:
- Run 1: the grammar-constrained harness worked with a fake model, but no real model could run.
- Run 2: the run environment has no Python, no llama.cpp and no Ollama. A 2.1 GB quantised model downloaded in about 11.5 s, but nothing could load it.

Two routes were not tried: a prebuilt llama.cpp binary, and a source build. The network is not the bottleneck; the missing inference engine is (B65–B67, B90, B91).

**X08.** Run 1 FAIL: the exact-term gate let all 10 paraphrase evasions through. Run 2 added a synonym-and-number layer, which caught 20/20 with 0/20 false positives on clean candidates. Run 2 is still INCONCLUSIVE, for two reasons. The paraphrases and the synonym table came from the same fixtures, with no held-out set. And the judge was simulated (B68–B70, B92, B93).

**X09 (deterministic).** PASS on detection. The append-only log caught 18 of 20 silent rewrites; the two misses were collisions on one event. Edit-in-place caught none, which is true by construction because it has no detection mechanism. The kill line's retained/reused-knowledge clause was not measured. The readable view stays cheap through compaction (10.8×), but the raw log grows 10.7× over 1,000 edits and cannot be pruned (B72). There is no declaration schema yet (B73).

**X10 (simulated).** PASS. Refusals are honoured going forward across five years: none of the 13 refused bridges was offered. Two problems remain:
- The compacted view is not constant-size. It grows with courses and with the carry-over ledger (B74).
- Refusal semantics for data already stored are undefined, so readers disagree on whether old competency is history or a leak (B75, B76).

**X11 (simulated).** INCONCLUSIVE, with one firm negative. With exposure normalisation the decline rate is 0.167, not the misleading raw 0.907. Removing scarcity wording cleaned up the offers: an independent evaluator flagged 0/6. But the same audit flagged 11/11 atlas markers, so the steering risk moved rather than disappeared (B77). At this small cohort size, k-anonymity suppresses every hole (B78).

## What these runs say about the architecture

- **Exact-match keys keep failing on paraphrase and translation.** A semantic layer is needed above them, and it must be tested on held-out data. Evidence: X02 B20, X08 B68 and B92, X01 B51.
- **Schemas and validators get absence and extra keys wrong.** Non-nullable sub-objects reject valid "nothing here" turns, while validators that skip `additionalProperties` let wrong-key records through silently. Evidence: E03 B24 and B82, E09 B38.
- **Prompt-only safety walls are not enough.** Patched prompts stopped almost every minor, but one opener with no age cue walked through. Age needs a structural check. Evidence: E14 B49, B50, B86.
- **The per-learner record and its compacted view still grow without bound across courses and years.** Append-log plus compaction holds within a course, but a second-order fold is needed. Evidence: B03, X10 B74, X09 B72.
- **Everything so far ran on a single vendor.** Nothing has been certified on a second vendor, so every portability claim is unproven. Evidence: B08, E04.
- **Steering risk moves rather than vanishes.** Neutral wording removed steering from offers, but it reappeared in atlas markers, and only an independent audit caught it. Evidence: X11 B16, B77.
- **Simulated runs can inflate agreement, hit ceilings and grade their own homework.** Several results are therefore INCONCLUSIVE rather than positive. Evidence: X05 B60, X01 B87, E13 B84, X08 B92.
- **A small offline model is blocked by the runtime, not the network.** Downloads are fast, but there is no engine to run the model. Evidence: X07 B90, B91.

## Blocked

- **E02, and the cross-vendor half of E04.** These need a second vendor's API key. Everything in this round ran on a single vendor, so the dual-vendor certification question (B08) stays open.
- **E07.** This needs network access to Oak, which this environment does not have.
- **E10.** This needs a small-model runtime. X07's run 2 looked for one and found none: there is no Python, no llama.cpp and no Ollama. The model files download quickly, but nothing can load them. E10 cannot start until a runtime is provisioned.
- **X12.** This is the capstone and comes last by design. It depends on the earlier fixes landing and has not been run.
