# Findings: runs of 18-19 Oct 2026

This round ran E01–E14 and X01–X11 once on 2026-10-18, with run-2 follow-ups on
2026-10-19 for E03, E05, E13, E14, X01, X07 and X08. Most runs had models standing in for
the people (guide, learner, parent, reviewer); those are marked **simulated**. A few runs
were deterministic (E04, E06, E12, X07, X08). A negative result is still a result and is
reported as one. MetaDAX is a way to test how learning compounds, never the way; nothing
here is a verdict on the architecture as a whole. New bottleneck rows are B24–B93 in
`BOTTLENECKS.md`.

## Per-experiment notes

**E01 (simulated).** A guide ran a session end to end on the fixture course; all five objective nodes validated and no new bottlenecks appeared. The earlier depth-cap worry (B01) is confirmed fixed under v0.3.

**E03 (simulated).** The parent-mediated learner session ran to the end and saved, but the tutor-turn and event schemas reject valid turns: unused sub-objects set to null are refused, and a follow-up event has no enum value (B24–B27). Run 2 showed that an arm given prompt guidance produced zero sub-object errors, while an arm left to improvise drifted on enums and state types (B79–B82). The learner's view never showed the tutor's JSON state.

**E04 (deterministic subagents).** MP-01 went to 100% schema-valid, but a simulation-harness quirk — reasoning prose before the JSON — failed 17/27 cases at the parse gate (B28), and an MP-04 prompt still names an old schema version (B29). Cross-vendor certification, the card's real question, remains untested (B08).

**E05 (simulated).** Reuse decisions were strong once the fixture flaw is accounted for: adjusted precision 34/36 = 0.944. The trap nodes placed in the registry pollute the "must not reuse" test (B30) and run 2 showed the contamination reaching ordinary-new queries (B83). Naming the enum in the prompt fixed haiku's enum and confidence drift (B31, B33).

**E06 (deterministic).** A realistic full course bundle (~500 kB) downloads in about 96 s of the 300 s window at 50 kbps, so the incremental path fits; the first full download and the lack of resume in `git bundle` are the risks (B34, B35).

**E08 (simulated).** The pure-function oracle passed 100%, which is necessary but not sufficient: there is no browser/rendering gate yet, so a passing core can still ship a broken sketch (B36, B37).

**E09 (simulated).** Five of six parents' records could be filed as-is; one set carried 14 privacy errors and cannot. The validator does not enforce `additionalProperties`, so nine wrong-key entries pass silently (18/21 "valid") (B38–B41).

**E11 (simulated).** Ingest needs no schema change beyond S-7; course metadata is a separate gap (B42). At a 4 KB cap only 3 of 21 nodes survive and selection degrades to chronological order (B43).

**E12 (deterministic).** All 12 cases were handled correctly — 11 tampers detected and 1 clean case correctly passed. Per-commit verification is slow at scale (~80 h for 4M commits, B44) and `ssh-keygen` is absent in some environments (B45, workaround shipped).

**E13 (simulated).** Run 1 passed on a substituted variant; the card's own variant is untested, and no FORGE operation exists (B46–B48). Run 2 is INCONCLUSIVE: the variant is schema-valid 10/10 and shows the method's surface features, but the method-literate reviewer the card requires was not run (B84, B85).

**E14 (simulated).** The age wall failed in run 1: zero stops on eight explicit minors and a 100% adversarial bypass (B49, B50). The run-2 proposed fix closed 21 of 22 probes; a bare "skip the age check" demand with no minor cue still slips past the interview mode, which needs a structural check rather than cue detection (B86). The homeschool and tutor skill patches stopped 13/13 with no adult false-stops.

**X01 (simulated).** Both runs are INCONCLUSIVE. Reuse of a captured move matched but did not beat a control that reinvents it, and run 2 hit a ceiling (every arm resolved 6/6), so the reuse-vs-no-technique gap (0.16) sits inside the run-to-run noise (0.67) (B51–B53, B87–B89). The move turned out to be discoverable on demand, so a record's value is likely portability, not speed.

**X02 (simulated).** The federation fixes hold in simulation: per-module plus append-only storage cuts conflicts/100 from 81.0 to 13.6 (−83%), the accepted-lifecycle gate drops cross-fork propagation of unreviewed nodes from 841–854 to 0, and a stored inverted index is ~80× faster. Closing paraphrase dedup still needs a model judge, which has a cost (B54, B55).

**X03 (simulated).** The override-record mechanism is sound, but a modelled expert reviewer cleared a node that omitted two escalation triggers — review catches commission errors, not omissions (B56), and prohibitions live in prose rather than a structural gate (B57).

**X04 (simulated).** Markers now attach to the node by opaque id, and the atlas rebuilds from the registry alone, byte-identical to the log-built version; the main stall became one hole carrying three sessions instead of three fragments. Unvalidated stall records still produce thin holes (B58, B59).

**X05 (simulated).** INCONCLUSIVE: with one model acting as both learner and evaluator, the 0.95 agreement is an artifact of shared interpretation, not cross-instrument validation (B60). The rubric also over-fires in densely scaffolded concepts (B61), and downstream-advance was not measured (B62).

**X06 (simulated).** The sharded index gives an 866× lookup speedup at 10⁵ entries and fixes B02; at a 100-course library each learner still pulls shard overhead (B63), and a first-session bootstrap miss caps the cache-hit rate at 97% (B64).

**X07 (deterministic).** Feasibility only. Run 1 found no llama.cpp, no Ollama and no GPU runtime; run 2 found no Python runtime at all. A 2.1 GB quantised model downloads in about 11.5 s (~183 MB/s), so the network is not the bottleneck — the missing inference engine is (B65–B67, B90, B91).

**X08 (deterministic).** Run 1's exact-term gate blocked 0 of 10 paraphrase evasions. Run 2's synonym-and-number layer blocked 20/20, but the verdict is INCONCLUSIVE: the paraphrases, synonym table and judge are all self-made, with no held-out set and a simulated judge (B68–B70, B92, B93).

**X09 (simulated).** Nothing-erased compounding detects tampering 100% of the time, dropping to 90% only when two silent edits collide on one event (B71). The readable view stays cheap via compaction (10.8×), but the raw log grows 10.7× over 1 000 edits and cannot be pruned (B72); there is no declaration schema yet (B73).

**X10 (simulated).** Forward-looking refusals are honoured cleanly across five years, but the compacted view is not constant-size — it grows with courses and the carry-over ledger (B74) — and refusal semantics for already-stored data are undefined, so readers disagree on whether old competency is history or a leak (B75, B76).

**X11 (simulated).** With exposure normalisation the decline rate is 0.167, not the misleading raw 0.907. Removing scarcity wording cleaned the offers (0/6 flagged by an independent evaluator) but the same audit flagged 11/11 atlas markers — the steering risk moved rather than disappeared (B77) — and k-anonymity suppresses every hole at this small cohort size (B78).

## What these runs say about the architecture

- Exact-match keys keep failing on paraphrase and translation, so a semantic layer is needed above them. Evidence: X02 B20 (0/30 hash recall), X08 B68 (0/10 blocked), X01 B51.
- Schemas are too strict about absence: non-nullable sub-objects and `additionalProperties: false` reject valid "nothing here" turns, so the learner path needs nullable fields or a client gate. Evidence: E03 B24, B82.
- Validators that skip `additionalProperties` let wrong-key records through silently, which is a privacy and integrity risk. Evidence: E09 B38 (9 wrong-key entries pass).
- The per-learner record and its compacted view both still grow without bound across courses and years; append-log plus compaction holds within a course but needs a second-order fold. Evidence: B03, X10 B74, X09 B72.
- Single vendor is still the rule — nothing has been certified on a second vendor, so every portability claim is unproven. Evidence: B08, E04, E09, E13, X07, X08.
- Neutral wording removed steering from offers but it reappeared in atlas markers, and it was only caught by an independent audit: steering risk moves rather than vanishes. Evidence: X11 B16, B77.
- Simulated runs can inflate agreement and hit ceilings, so several results are INCONCLUSIVE rather than positive. Evidence: X05 B60 (0.95 same-model agreement), X01 B87 (6/6 ceiling).
- A small on-phone model is blocked by the runtime, not the network: downloads are fast but there is no engine to run the model. Evidence: X07 B90, B91.

## Blocked

- **E02 and the cross-vendor half of E04** need a second vendor's API key. Everything in this round ran on a single vendor, so the dual-vendor certification question (B08) stays open.
- **E07** needs network access to Oak, which this environment does not have.
- **E10** needs a small-model runtime. X07's run 2 looked for one and found none: the container has no Python, no llama.cpp and no Ollama, and while a 2.1 GB quantised model downloads in about 11.5 s, there is nothing to load or run it with. E10 cannot start until a runtime is provisioned.
- **X12** is the capstone and comes last by design; it depends on the earlier fixes landing and has not been run.
