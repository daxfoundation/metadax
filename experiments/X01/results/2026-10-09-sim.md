## BOTTLENECKS (each with evidence)

**B18. There is no technique record in the schema — the whole X01 primitive is unexpressible.**
Evidence: `tutor-turn.schema.json` v0.2 has `type`, `state`, `feedback`, `handoff` but **no** `stuck_signature`, **no** `chain_role` (a human-tutor move and a model hint are structurally identical — "chain_role: tutor" cannot be recorded), **no** `technique_id`/`technique_ref`, and **no** technique object type anywhere (node/registry/tutor-turn). The X01 technique record (`X01-technique-record.json`) had to invent `metadax.technique/0.0-PROPOSED`. Nine concrete missing fields enumerated there.

**B19. Merge conflicts: single-file is pathological, per-module is merely bad.**
Evidence: conflicts/100 commits = **97.3 (single file)** vs **86.5 (per-module)**, same seed, same workload (`part-a-results.json`). Per-module files are necessary but insufficient: Zipf topic concentration pushes most follow-ups onto a few hot modules (`L01.M01` and `L03.M01` carry the most nodes in `sample-registry/es/registry-index.json`), so contention stays high. A per-module file is still a single serialization point under concurrent learner writes.

**B20. Near-duplicate drift is bounded only by exact content-hash matching.**
Evidence: without the federated index, 228 near-duplicates formed (identical content key, separate nodes across forks). With it, 0 — but *only because the simulation's content hash is exact*. Real paraphrase and cross-language translation will slip under an exact hash, so the true near-dup count in production is **> 0 and unmeasured here**. The index is a hash join; it does not do semantic dedup.

**B21. The pending_review → accepted lifecycle and `contested` flag do not exist.**
Evidence: `node.visibility` is `private|pending_review|shared` with **no** `accepted_by`/`reviewed_by` provenance for the transition, and **no** `contested` flag to keep two cores/techniques side by side. X01's "accepted by a teacher" and X02's "contested cores kept side by side" both had to be faked in the result JSON. Federation currently indexes `pending_review` nodes as reusable (contract point 8), meaning unreviewed learner content propagates cross-fork before any teacher sees it.

**B22. Index size / growth.**
Evidence: the no-index registry grew to 552 nodes from 2,000 follow-ups; the federated index holds the union of all 4 forks' registries read-only. Growth is dominated by `extend` and `new` decisions; `reuse`/`ancestor` (1873/2000 federated) add no nodes. The federated index must re-scan this union per follow-up candidate lookup — O(union) per call — with no stored inverted index on stuck-signature or content key (bottleneck B18 again: there's no key to query).

**B23. Cost per session (Part B).**
Evidence: 3 model-played session-groups cost ≈ 8.4–8.9k output tokens each (~26k total) for 7 learner sessions. At that rate a single stuck-signature study of a few hundred learners is affordable; a per-learner live tutor-move-capture loop at population scale is the cost risk, not the storage.

## What only real people can answer

- **Does an offered technique actually unstick a *real* learner faster, or does the simulation just encode the hypothesis?** The 5.5 → 2.33 gap is baked into how the subagents were told to behave. Only a real A/B with real learners can measure it.
- **Does the "two receipts" move survive translation and culture?** A simulated learner accepted the receipt metaphor in es/de unchanged; a real Spanish/German teacher may find it lands badly or needs a local reframe. Only they can judge.
- **What counts as the *same* stuck signature?** Deciding that an `es` learner's confusion is the same signature as an `en` learner's is a human pedagogical judgement; an exact content hash cannot make it (bottleneck B20).
- **Which contested cores deserve to be kept side by side vs merged?** The schema can hold a `contested` flag, but only teachers can decide what is genuinely contested knowledge vs a fixable error.
- **Is cross-fork propagation of `pending_review` content acceptable?** Whether unreviewed learner nodes should be reusable across forks before a teacher accepts them is a governance/safety call for the steward, not a code default.
