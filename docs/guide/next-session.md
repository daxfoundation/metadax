# Session two, the learning record, and several kids

Meta DAX › [Help](index.md) › Next session

One lesson is a start. The point is the next one, and the one after. Here is how to
keep going — from the note the page leaves, the record you keep, and teaching more
than one child at once.

## Session two, from the next-time note

The learner page leaves a short **next-time note** — a few lines about how the
session went. When you come back, give that note to the skill or the AI chat (paste
it in, or point it at the file you saved) and ask for the next session. It builds
session two straight from it:

- it keeps what worked, and opens with a callback to it rather than starting over;
- it moves one step on from the stuck spot — one step, never a leap — and never
  repeats a thing the note says already failed;
- it changes the game's theme only if the note says your child tired of it;
- it paces the length and tone to how the last one ended.

It keeps a small `family-progress.json` on your own machine so it remembers where
you are next time. That file is private and is never uploaded.

## The learning record

A learning record is one short, dated entry per session that you add to over time —
readable by you and by a program. There are two easy ways to keep one:

- In the player, at the end of a session, you are offered the chance to **save that
  session to a learning record**. It downloads a file to your device; nothing is
  uploaded.
- Or, after you have actually run the session, the skill (or AI chat) can write a
  record entry for you: which games you played, the slips that kept coming up —
  described as behaviour, never as a label — something your child said, and your
  own note on the hardest moment.

The record stays on your machine. If you ever want to keep it in its own place,
there is a template repository you can copy; it stays private until you choose, in
one step, to publish it.

[The learning-record template →](https://github.com/daxfoundation/metadax-learner-record)

## Several children at once

If more than one child does the same lesson together, you answer the questions
**once for the group** — a nickname and a rough age for each child — not once per
child. The package then carries each child, and every part shows who does it: one
child reads a part, the little ones do the hands-on part, the oldest gets the
explaining part. In the player and in print, a small label on each part says whose
it is.

Adding another child to the family later, or the same child on a new subject,
reuses what you already answered — you are not interviewed from scratch.
